In juggling, siteswap is used to notate juggling patterns. The simplest juggling pattern, juggling three balls at the same height, is notated 3, as we throw a ball and catch it three beats later. This can be thought of as going on forever, so it is really ...3333333... Another juggling pattern is 51, where a ball in one hand is thrown high and the other is passed very low and directly to the other. Expanded, it is ...51515151...

There are infinitely many possible siteswaps. Yet, not every juggling pattern is "interesting". For example, the pattern 42333333333333 is just the three ball cascade except a 42 is inserted every 12 throws. The usual common notion of what an interesting siteswap is a prime siteswap. This is where we define the state as the current delays until each ball meets the hand. This is a much more restricted set, but even this is a bit too permissive. For example, the pattern 900 is essentially just 3 except scaled up in time and height. And there are still infinitely many prime siteswaps.

To solve this, we instead define the state as the queue of current falling balls to each hand, remembering which ball is which and forgetting the time to fall of each ball. For example, (ab c) has ball a falling to the left hand followed by ball b falling but still higher in height, and ball c falling to the right hand. We then define an interesting siteswap as one that does not repeat one of these stack states. One consequence of this is that there are finitely many states, and therefore only finitely many interesting siteswaps.
